# 05. 사용자 테스트 계획서

> 미션 필수 요건: **실제 사용자 최소 5명 이상에게 서비스를 제공하고 피드백을 수집·반영**한다.
> 결과는 `06_사용자_테스트_결과.md` 양식에 기록한다.

## 1. 목적
기획서의 가설(H1~H4)을 실제 사용자로 검증하고, 개선점을 찾아 v1.1에 반영한 뒤 **개선 효과를 다시 측정**한다.

| 가설 | 확인 방법 |
|---|---|
| H1 출처가 붙은 자료 기반 답변을 신뢰한다 | 👍 비율, 설문 2번, 인터뷰 |
| H2 퀴즈 → 약점 기억 → 재설명이 복습에 도움된다 | 과제 T5 수행·'다시 배우기' 사용 여부, 인터뷰 |
| H3 장기 기억이 개인화로 느껴진다 | 과제 T4·T8, 인터뷰 |
| H4 3분 안에 첫 질문까지 간다 | 관찰 세션 소요 시간, 설문 3번 |

## 2. 테스트 개요

| 구분 | 1차 테스트 | 2차 테스트 |
|---|---|---|
| 버전 | v1.0.0 (MVP) | v1.1.0 (1차 피드백 반영) |
| 시기 | 3주차 월~수 | 4주차 월~수 |
| 인원 | **5명 이상** (목표 8명) | 1차 참여자 중 3명 이상 + 신규 2명 이상 |
| 방식 | 관찰 세션 3명 이상(20분) + 자율 사용(3일) | 자율 사용 + 짧은 인터뷰 |
| 산출 | 문제 목록, 개선 이슈 | 버전별 만족도 비교, 개선 효과 |

- 피드백에는 **앱 버전이 자동 저장**되므로 관리자 화면의 '버전별 피드백 평균'으로 v1.0 ↔ v1.1을 바로 비교할 수 있다.

## 4. 사전 안내 (테스트 시작 시 읽어 주기)
- 이 서비스는 **AI가 생성한 답변**을 제공하며 틀릴 수 있습니다.
- 닉네임에 실명을 쓰지 말고, 개인정보가 담긴 자료는 올리지 말아 주세요.
- 가입 화면의 개인정보 안내를 읽고 동의한 경우에만 참여합니다. 언제든 중단하고 데이터를 삭제할 수 있습니다.
- 관찰 세션은 화면 공유로 진행하며, **녹화는 별도로 동의한 경우에만** 합니다.
- 서비스를 평가하는 것이지 여러분을 평가하는 것이 아니니, 불편한 점을 솔직하게 말해 주세요. (생각을 소리 내어 말해 주시면 큰 도움이 됩니다)

## 8. 사후 인터뷰 질문 (5분)
1. 평소에 공부하다 막히면 어떻게 해결하나요? StudyMate와 비교하면 어땠나요?
2. 답변을 믿을 수 있었나요? 출처 표시가 그 판단에 영향을 줬나요?
3. AI가 시험 일정이나 약점을 기억하는 게 도움이 됐나요, 부담스러웠나요?
4. 퀴즈 문제의 품질과 난이도는 어땠나요?
5. 가장 불편했던 순간 하나만 꼽는다면?
6. 이 서비스를 다음 시험 때 또 쓸 것 같나요? 왜 그런가요?
7. 하나만 바꿀 수 있다면 무엇을 바꾸고 싶나요?

## 9. (선택) Google Form 상세 설문
앱 안 설문으로 필수 데이터는 모두 모인다. 더 깊은 의견이 필요하면 아래 문항으로 Google Form을 만들고, 링크를 `FEEDBACK_FORM_URL`에 넣으면 피드백 화면에 버튼이 생긴다.

1. 테스터 코드 또는 닉네임 (단답, 선택)
2. 사용한 자료 종류: 강의 PDF / 필기 노트 / 교재 요약 / 샘플 자료 / 기타 (체크박스)
3. 가장 유용했던 기능: 자료 기반 답변 / 출처 표시 / 퀴즈 / 약점 기억 / 학습 기록 (체크박스)
4. 가장 아쉬웠던 기능과 이유 (장문)
5. 답변 속도는 어땠나요? 빠름 / 적당 / 느림 / 매우 느림 (객관식)
6. 답변 길이는? 너무 짧음 / 적당 / 너무 김 (객관식)
7. 퀴즈 난이도는? 너무 쉬움 / 적당 / 너무 어려움 (객관식)
8. 기존 공부 방식(범용 챗봇, 검색, 질문방 등)과 비교해 더 나은 점·못한 점 (장문)
9. 추가됐으면 하는 기능 (장문)

## 10. 분석 → 개선 절차
1. **수집**: 관리자 화면에서 피드백 CSV 다운로드, 관찰 기록표·인터뷰 메모 취합
2. **분류**: 의견을 포스트잇 1장 = 1의견으로 옮겨 비슷한 것끼리 묶기(친화도 분석) → 묶음마다 언급 인원 수 기록
3. **우선순위**: 영향도(언급 인원 × 심각도) × 개발 난이도로 4분면 배치 → "영향 큼·쉬움"부터 처리
4. **이슈화**: 처리할 항목은 GitHub Issue(`feedback` 라벨, 피드백 템플릿)로 등록, 담당자·마감 지정
5. **반영·배포**: PR → 리뷰 → main merge(자동 재배포) → `APP_VERSION`을 1.1.0으로 올리고 `CHANGELOG.md` 기록
6. **재측정**: 2차 테스트 후 버전별 만족도·👍 비율 비교 → `06_사용자_테스트_결과.md`에 개선 효과 기록

## 11. 빠르게 조정할 수 있는 개선 레버 (참고)
테스트 결과에 따라 코드를 크게 고치지 않고 바로 손볼 수 있는 지점이다. **실제 어떤 피드백이 나올지는 테스트 후에 판단한다.**

| 이런 피드백이 나오면 | 먼저 조정할 곳 |
|---|---|
| 답변이 길다/짧다 | `prompts.py` 행동 원칙 ⑥ |
| 답변이 느리다 | `REASONING_EFFORT`(low→off 가능 모델로), `CHAT_MODEL`, 검색 `RETRIEVAL_TOP_K` 축소 |
| 자료에 있는데 못 찾는다 | `RETRIEVAL_MIN_SCORE` 낮추기, `RETRIEVAL_TOP_K` 늘리기, `scripts/eval_rag.py`로 청크 크기 비교 |
| 엉뚱한 출처가 붙는다 | `RETRIEVAL_MIN_SCORE` 높이기 |
| 퀴즈가 쉽다/어렵다 | `prompts.py`의 `DIFFICULTY_GUIDE` |
| 기억이 너무 많이/적게 저장된다 | 시스템 프롬프트 원칙 ③의 저장 기준 문장 |
| 처음에 뭘 해야 할지 모르겠다 | 첫 화면 안내 문구, `SUGGESTED_PROMPTS`, 샘플 자료 버튼 위치 |
