## 2. 기능 요구 사항

| 미션 요구 | 대응 | 상태 |
|---|---|---|
| 생성형 AI 또는 AI Agent가 핵심 기능 | AI 튜터 Agent(Function Calling, 도구 3개), 자료 기반 퀴즈 생성 | ✅ |
| 실제 사용자 최소 5명에게 제공·피드백 수집 | 배포 + 앱 내 피드백/👍👎 + 테스트 계획(1차 5명 이상, 2차) | 🔲 실행 |
| 필수 기술 요소 2개 이상 | **AI Agent ✅ · RAG ✅ · Long-term Memory ✅ · 자동화 워크플로우 ✅(n8n)** — 4개 | ✅ |
| 팀 3~5인, 역할 분담, 모두 실질적 기여 | 5인 역할·담당 코드 지정, 3·4인 통합안, 이슈별 담당, 기여 기록 팁 | ✅ 계획 / 🔲 팀원 배정 |
| 해결할 문제를 명확히 정의 | 기획서 1장 (배경·문제 진술·HMW·가설) | ✅ |
| 서비스 아키텍처 설계·문서화 | 요구 명세서 5·6장 (구성도, 시퀀스, ERD) | ✅ |
| AI 활용 방식(프롬프트, Agent 구조, RAG 등) 설계·문서화 | `docs/03_AI_설계서.md` | ✅ |
| 진행 과정 문서화 | `docs/07_개발_진행_기록.md` (주간 기록·회의록·AI 도구 활용·회고) | ✅ 양식 / 🔲 진행하며 기록 |
| README에 개요·팀원 역할·기술 스택·실행 방법·결과 | `README.md` | ✅ / 🔲 팀원 이름·URL·결과 수치 |
| Git으로 체계적 버전 관리 | 브랜치·커밋 규칙, 마일스톤, 태그, CI | ✅ 규칙 / 🔲 실행 |
| 외부 접근 가능한 배포 | Streamlit Community Cloud + Supabase | 🔲 실행 |
| 실사용자 테스트 후 피드백 반영 | 버전 자동 기록 → 버전별 만족도 비교, CHANGELOG, 결과 보고서 3장 | ✅ 구조 / 🔲 실행 |
